# Evaluation Recipe

Minimal, reproducible recipes to evaluate the free 50-row trials **before** purchasing full volumes.

## What the trial is for

The 50-row trial exists to let you verify three things on your own stack:

1. **Schema integrity** — every row parses as strict JSONL and matches the published `schema.json`
2. **Multi-turn / tool-use behavior** — role sequences, tool definitions, and arguments are structurally consistent
3. **CoT step structure** — `reasoning_steps` are well-formed, ordered, and end in an explicit conclusion (CoT dataset)

If the trial passes your pipeline, the full volume will too — the schema is identical.

## 1. Programmatic metrics (no GPU required)

```bash
python evaluation/eval_metrics.py path/to/data.jsonl
```

Reports:

| Metric | Meaning | Applies to |
|---|---|---|
| `json_schema_pass_rate` | rows that parse and contain all required fields | all |
| `tool_call_valid_rate` | tool definitions parse as a valid JSON schema array | MCP / FC-EN / FC-JA |
| `turn_consistency_rate` | user-led role sequence, non-empty turns | MCP / FC-EN / FC-JA |
| `reasoning_step_consistency` | non-empty ordered steps + explicit conclusion | CoT |

Expected result on the published trials: **100% on all applicable metrics** (see the Schema Validation Summary image on each HF dataset card — generated by this same class of checks).

## 2. Axolotl (fine-tuning smoke test)

The conversation datasets (`{id, tools, conversations[{from, value}]}`) are ShareGPT-shaped.
Minimal config: [axolotl_config.yaml](axolotl_config.yaml)

```bash
axolotl train evaluation/axolotl_config.yaml
```

This is a smoke test (LoRA, small base model) to confirm the data loads and tokenizes cleanly in your pipeline — not a benchmark.

## 3. Unsloth (loading check)

Minimal loading snippet: [unsloth_load.py](unsloth_load.py)

```bash
python evaluation/unsloth_load.py path/to/data.jsonl
```

Confirms rows convert to your chat template with zero formatting errors.

## What is guaranteed vs. not guaranteed

**Guaranteed (verifiable from the data itself):**
- Strict JSONL — 1 row = 1 valid JSON object
- Schema conformance to the published `schema.json`
- Multi-turn role-sequence consistency
- `tools` / arguments structural integrity (conversation datasets)
- `reasoning_steps` format integrity (CoT dataset)
- Zero row overlap across lots (hash / ID / 3-gram Jaccard audited, SHA256SUMS included)

**Not guaranteed (depends on your model, stack, and jurisdiction):**
- Any specific performance uplift for a given model
- Legal compliance of your deployment in any specific jurisdiction
- Exhaustive coverage of all regulatory texts (CoT covers selected regulations; see dataset card)
